## Course purpose

**Introduction to Python** is a first text-based programming course designed for secondary students with no prior coding experience.

Students progress from producing simple output to designing structured programs that make decisions, repeat processes, organize code with functions, and work with collections of data.

The course emphasizes:

- writing code that runs and produces intended results;
- reading errors as useful debugging information;
- computational thinking and problem decomposition;
- readable, documented programs;
- applied programming tasks rather than syntax recall;
- gradual movement from Python code to broader algorithmic reasoning.

All current Python examples and interpreter output used in the curriculum are verified through execution on **Python 3.12** before publication.

The sequence is intentionally cumulative: students first learn to communicate precisely with a computer, then store information, make decisions, automate repeated work, decompose larger problems, process collections of data, and finally apply those skills in an original project.

## Instructional design features

### Debugging is taught early

Students encounter traceback reading in Unit 1 rather than waiting until errors become frustrating. The goal is to establish debugging as a normal programming practice from the beginning.

### Programs are built for a purpose

Each unit moves toward an applied programming outcome. Students are expected to create, test, revise, and explain working code rather than demonstrate knowledge through vocabulary recall alone.

### Documentation is part of programming

Readable code and purposeful comments are treated as design decisions, not afterthoughts.

### Decomposition is taught before complexity grows

Functions and planning strategies are introduced as tools for managing larger problems, preparing students for more independent project work.

### Python connects to broader algorithmic thinking

Later units incorporate opportunities to express programming logic in pseudocode so students can separate underlying algorithms from language-specific syntax.

## Assessment approach

The complete course uses a combination of:

- brief formative checks;
- coding practice;
- debugging tasks;
- unit performance checkpoints;
- code review and explanation;
- project-based assessment;
- a final capstone program.

Assessment prioritizes whether students can apply programming concepts, reason about code behavior, debug problems, and communicate design decisions.

Detailed assessment instruments, rubrics, answer keys, and teacher solutions are not published in this public repository.
